# altv Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build altv — a self-hosted TradingView alternative with charts, indicators, drawings, watchlist and custom chained baskets — for US stocks/ETFs (incl. extended hours) and crypto.

**Architecture:** pnpm TypeScript monorepo. `packages/shared` holds types and pure, heavily-tested math (time/session helpers, resampling, basket engine). `apps/server` (Fastify + Kysely over SQLite/Postgres) wraps market-data providers behind one interface, caches bars with coverage tracking, and serves baskets as ordinary symbols. `apps/web` (React + Vite) renders charts through a single `ChartAdapter` module around KLineChart v10.

**Tech Stack:** Node 22, pnpm 8, TypeScript 5.9, Vitest 5, Fastify 5, Kysely 0.29 (better-sqlite3 13 / pg 8), zod 4, yahoo-finance2 4, React 19, Vite 8, klinecharts 10, Playwright 1.64.

**Spec:** `docs/superpowers/specs/2026-10-11-altv-design.md`

## Global Constraints

- Node `>=22`; package manager pnpm (workspace). All packages `"type": "module"`.
- TypeScript `~5.9.3`, `strict: true`, `noUncheckedIndexedAccess: true`.
- `packages/shared` and `apps/server` use `module`/`moduleResolution: NodeNext`: relative imports MUST use `.js` extensions (`import { x } from './nytime.js'`). `apps/web` uses `Bundler` resolution (no extensions needed).
- All timestamps are **UTC epoch milliseconds** (`number`). Bar `ts` is the bar **start**.
- Daily-and-above bar `ts` = `Date.UTC(y, m, d)` of the bar's trading date (exchange-local date for stocks, UTC date for crypto). Weekly bars start Monday; monthly bars start on the 1st.
- Symbol ids: `stock:<TICKER>` (e.g. `stock:AAPL`), `crypto:<BASE>` (e.g. `crypto:BTC`, always priced in USD; Binance maps to `BTCUSDT`, Coinbase to `BTC-USD`), `basket:<uuid>`.
- Timeframes (exact strings): `1m 5m 15m 30m 1h 2h 4h 1D 1W 1M`.
- Sessions: query param `session=rth|eth`; bar tag `session?: 'pre'|'regular'|'post'` (stocks intraday only).
- API error body: `{ "code": string, "message": string }` with appropriate HTTP status.
- Only `apps/web/src/chart/ChartAdapter.ts` (and files under `apps/web/src/chart/`) may import `klinecharts`.
- No live network in automated tests. Provider tests use recorded fixtures in `apps/server/test/fixtures/`.
- Env vars: `PORT` (default 8787), `DATABASE_URL` (default `sqlite:./data/altv.db`; `postgres://…` selects Postgres), `ALTV_PASSWORD` (optional), `ALTV_SESSION_SECRET` (optional; derived from password if unset), `CRYPTO_PROVIDER` (`binance` default | `coinbase`), `BINANCE_BASE_URL` (default `https://data-api.binance.vision`), `ALTV_PROVIDERS` (`live` default | `fixture` — fixture mode serves deterministic synthetic data for e2e).
- Commit after every task with a conventional message and the trailer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

### Deliberate deviations from the spec (documented)

1. **Kysely instead of Drizzle.** Drizzle schemas are dialect-specific, so supporting both SQLite and Postgres would need two schemas. Kysely gives one typed query layer and portable migrations for both.
2. **Crypto ids are `crypto:<BASE>`** rather than `crypto:BTCUSDT`, so switching between Binance and Coinbase does not invalidate saved baskets/watchlists/drawings.
3. **No custom `SMA` registration.** KLineChart's built-in `MA` is the simple moving average; the UI labels it "Moving Average (SMA)". (KLineChart's built-in `SMA` is a different, weighted average and is labelled as such.)
4. **Basket version timing is day-granular** (see Task 3): a version's `effectiveFrom` is a calendar date; new weights are sized at the prior trading close and apply from 00:00 UTC of that date on every timeframe. This makes units identical across all timeframes (no per-timeframe drift) and gives exact continuity on RTH charts.
5. **1W/1M are always resampled from 1D**, and 2h/4h from 1h, for every provider (Yahoo's native weekly/monthly responses contain a trailing "live" duplicate bar; resampling avoids it and keeps all providers consistent).

## Review Focus

1. **DST transitions** (March/November): session tagging and RTH/ETH 2h/4h bucketing must use America/New_York local time, not a fixed UTC offset — Task 1/2 tests pin a bar on both sides of each transition.
2. **Basket with a constituent that lists after T0** (e.g. backdated to 2015 with a 2020 IPO): series must start at the first date every constituent has a prior close, with a notice naming the limiting symbol — Task 3 test.
3. **Provider outage / 429 while the cache has data**: API must return cached bars with `stale: true`, never a 500 — Task 6 test.
4. **Requests beyond provider lookback** (1m older than ~30 days, 1h older than 730 days): must return what exists with `hasMoreBefore: false`, not an error, and must not hammer the provider — Task 6 test.
5. **Half-day sessions** (e.g. day after Thanksgiving, 13:00 close): bars after the early close must be tagged `post`, using Yahoo's `tradingPeriods` — Task 5 fixture test.

**Interfaces:**
- Consumes: Task 1 (`Bar`, `Timeframe`, `nyParts`, `nyToUtc`, `nyDateUtcMidnight`, `tfMs`).
- Produces:

```ts
// session.ts
export interface SessionWindow { start: number; end: number; session: Session } // [start, end)
export function tagSessionFixedHours(ts: number): Session | null; // NY: 04:00–09:30 pre, 09:30–16:00 regular, 16:00–20:00 post, else null
export function tagSessions(bars: Bar[], windows?: SessionWindow[]): Bar[]; // windows win when a bar falls in one; otherwise fixed hours; bars outside all sessions are dropped
export function filterSession(bars: Bar[], mode: SessionMode): Bar[]; // rth → keep bars with session undefined or 'regular'; eth → all
// resample.ts
export type Calendar = 'utc' | 'nyse-rth' | 'nyse-eth';
export function bucketStart(ts: number, tf: Timeframe, calendar: Calendar): number;
export function resample(bars: Bar[], tf: Timeframe, calendar: Calendar): Bar[];
```

Bucket rules (`bucketStart`):
- `1W`: Monday 00:00 UTC of the week containing `ts` (bars are UTC-midnight dates). `1M`: 1st of month 00:00 UTC. `1D`: `ts` itself floored to UTC midnight.
- Intraday, `calendar='utc'`: `Math.floor(ts / tfMs) * tfMs`.
- Intraday, `nyse-rth`: anchor = `nyToUtc(NY date of ts, 09:30)`; `anchor + floor((ts − anchor)/tfMs)*tfMs`. `nyse-eth`: anchor 04:00 NY. (If `ts < anchor`, floor still works — negative index — but such bars only occur in ETH before 04:00, which do not exist.)
- `resample`: group consecutive bars by bucket (input sorted ascending); output `{ ts: bucket, open: first.open, high: max, low: min, close: last.close, volume: sum }`; session of output = session of the first bar if all bars in the bucket share it, else `undefined`. Empty input → `[]`. Never mutates input.

export class BasketValidationError extends Error {}
export function validateVersions(versions: BasketVersion[]): void;
//  throws BasketValidationError when: no versions; a version has no weights; any weight ≤0 or not finite;

export function buildBasketBars(units: UnitsResult, series: ConstituentSeries[]): Bar[];
export function versionMarkers(units: UnitsResult): Marker[]; // one per version k ≥ 1: { ts: effectiveTs, label: `v${k+1}` }

**Semantics (must match exactly):**
- `priorClose(id, ts)` = close of the last daily bar of `id` with `bar.ts < ts`; `undefined` if none.
- **Version 0:** requested start `T = parseDateString(v0.effectiveFrom)`. Effective start `S` = smallest `ts ≥ T` such that every constituent has `priorClose(id, ts) !== undefined`, where candidate `ts` values are `T` and each constituent's daily bar timestamps + 1 day (i.e. the day after each first bar). Concretely: `S = max(T, max over ids of (firstBar(id).ts + 86_400_000))`. If `S > T`, push notice `Basket starts ${utcDateString(S)}: ${limitingId} has no data before that date.` (limitingId = the id whose first bar determined S). If some constituent has no daily bars at all → throw `BasketValidationError('No data for ' + id)`. Units: `units_i = w_i × baseValue / priorClose(i, S)`; `levelAtStart = baseValue`.
- **Version k ≥ 1:** `Tk = parseDateString(effectiveFrom)`; if `Tk ≤ S` (start of v0) throw `BasketValidationError('Version ' + (k+1) + ' starts before basket start')`. `L = Σ_{i in prev} units_prev_i × priorClose(i, Tk)`; every id in the new version must have `priorClose(id, Tk)` else throw `BasketValidationError('No data for ' + id + ' before ' + effectiveFrom)`. Previous-version constituents use priorClose too (they have data since they were valid before). `units_i = w_i × L / priorClose(i, Tk)`; `effectiveTs = Tk`; `levelAtStart = L`.
- `startTs = S` (v0 `effectiveTs = S`).
- **buildBasketBars:** timeline = sorted union of all `bar.ts` across `series` with `ts ≥ startTs`. Walk the timeline keeping each constituent's last close (seed: last bar with `ts < startTs` per series, if any). For each `t`: active version = last version with `effectiveTs ≤ t`. For each id in that version: if the series has a bar at `t` use its OHLC, else if a last close exists use `O=H=L=C=lastClose`, else **skip the timestamp entirely** (not all constituents have a value yet). Output bar = `Σ units × O`, `Σ units × H`, `Σ units × L`, `Σ units × C`, `volume: 0`, no session. A series id required by a version but absent from `series` is treated as having no bars (so timestamps are skipped until... never) — callers must pass all ids.
- Precision: no rounding inside the engine.

**Algorithm `getNativeBars`:**
1. `provider = registry[assetClass]`. Clamp `from` to `now − limits.maxLookbackMs[tf]` if defined; clamp `to` to `now + tfMs`.
2. `recentEdge = now − 2 × tfMs(tf)` (for `1D`: `now − 3 days`). Coverage considered only up to `recentEdge`; the span `[max(from, recentEdge), to)` is **always** refetched.
3. `gaps = missingRanges(coverage, from, min(to, recentEdge))` ∪ the recent span; split each gap by `maxSpanPerRequestMs`; fetch each through the provider's queue with key `${symbol}|${tf}|${gapFrom}|${gapTo}`.
4. Upsert fetched bars; add coverage for each successfully fetched gap **clipped to `recentEdge`** (never mark the recent span as covered).
5. On `ProviderError` (retryable or not) or network failure: call `queue.backoff(30_000)` if retryable; set `stale = true`; continue with what's in the DB. `NotFoundError` propagates (→ 404).
6. Return `repos.bars.range(symbol, tf, from, to)`.

**`getBars`:** `base = baseTimeframe(tf)`; for stocks intraday, `getNativeBars` then `filterSession(mode)` then `resample(…, tf, calendarFor)` if `tf !== base`; for `1W`/`1M` resample daily with `'utc'`. Crypto: no session filter. `earliestTs = earliest(symbol, tf)`; `hasMoreBefore = earliestTs === null ? bars.length > 0 : from > earliestTs`. If the requested window was clamped by lookback, push notice `Free data source limits ${tf} history to ~N days.` (N = lookback days).

**`getLatest`:** window `from = bucketStart(now, tf, cal) − tfMs(tf)` (for 1W: − 7 d; 1M: − 31 d), `to = now + tfMs(tf)`; `getBars` → last bar or null.
